# Phase 06 – User interface

Dossier: `06-ui`. Spec: [`docs/UI-SPEC.md`](../UI-SPEC.md). That spec is the single source the UI team builds from;
this page records what the dossier contains and how AnyFont maps it.

## What the dossier says

| Source | Content |
|---|---|
| `06-ui/screenshots/` | screenshots of the real program in 13 selection contexts (deselect-all … user-collection-font-selected). Folders: `02-main-window`, `03-menus`, `04-toolbar`, `05-dialogs`, `06-panels` (filters, font-list, font-properties, libraries), `07-context-menus`, `08-title-bar`, plus reports in `90-reports` (`menus.json`, `toolbar-states.json`, `coverage.md`) |
| `06-ui/menus.md`, `menus.json` | the 72 command bars of `FontManagerUI.xml` with every item's guid, kind, caption and enable/check/visible/invoke binding |
| `06-ui/dialogs/*.md` | the 95 dialog definitions of `FontManagerUI.dialogs.xml` (control tree, data sources, bound strings) |
| `06-ui/screens.md`, `navigation.md`, `assets.md` | screen inventory, how screens are reached, icon assets |

The original UI is declarative. Every control is bound to a data-source property, for example
`enable -> FontDS.UninstallEnabled`. The program's behaviour is therefore the set of bindings plus the C++
handlers behind them. Most of the 95 dialogs belong to the drawing suite's shared text, colour, workspace and
cloud framework; they live in the same XML but Font Manager never opens them. Only 25 are Font Manager UI.

The captured window shows:
- a custom title bar with ?, gear and trial buttons;
- the menu bar File / Edit / Font / View / Help;
- a 10-button toolbar;
- Libraries and Filters on the left;
- the search row and the font list in the centre;
- an optional font properties panel on the right (Glyphs / Font info / Variable font);
- a status bar with the preview-size slider.

## How AnyFont implements it

### Crate layout (`crates/anyfont/src`, proposal for the UI team)

| Module | Implements (UI-SPEC section) |
|---|---|
| `app.rs` | eframe app, frame layout, splitters, global keys (§1, §8) |
| `titlebar.rs` | custom title bar, caption buttons, snap-layout hit test (§4) |
| `commands.rs` | the command table: id, caption (static or dynamic), icon, shortcut, `enabled(&State)`, `checked(&State)`, `visible(&State)`, `run`. Menus, toolbar and context menus all read this one table, so their rules cannot drift apart (§2, §3, §6) |
| `menus.rs` | menu bar and popup rendering with the §2.2 geometry; context menus |
| `toolbar.rs` | toolbar, tooltips with header and body, overflow (§3) |
| `libraries.rs` | Libraries panel, inline collection editor, drag-and-drop target (§5.1) |
| `filters.rs` | Filters panel (§5.2) |
| `fontlist.rs` | virtualised font list, family headers, preview rendering cache, selection model, type-ahead, empty states, MRU list, information strip (§5.3) |
| `properties/{glyphs,info,variable}.rs` | font properties panel (§5.4) |
| `statusbar.rs` | status text and preview-size slider (§1.4) |
| `dialogs/*.rs` | one file per dialog of §7.2 (about, sysinfo, legal, options, confirm_remove, delete_fonts, reboot, progress, not_found, message_box, catalog, updates, bugreport, panose_prefs, panose_exceptions, panose_results, type1, rename_collection) |
| `theme.rs` | the four themes, as tokens from `docs/design-tokens.md` (§10) |
| `i18n.rs` | translator (phase 08) |

Rendering notes:
- Font previews are rasterised by `anyfont-core` from the font file (ttf-parser + rustybuzz + tiny-skia). They
  are cached per (face, size, text) as egui textures.
- Fonts are **never** installed in order to preview them.
- The list is virtualised: only visible rows are laid out, with row heights taken from the preview size.

### Selection contexts and enable rules

The 13 captured contexts become test fixtures. Each fixture is a sandbox font set plus a sequence of UI
actions. For every fixture, a headless `egui_kittest` test checks that each menu, toolbar and context-menu
item's enabled, checked and visible state matches the tables in UI-SPEC §2–§3. The rules are written as
predicates over the selection, so they also cover states that were not captured.

### Deliberate differences from the original

| Original | AnyFont | Why |
|---|---|---|
| Product name, logo, About text, copyright | AnyFont, its own logo, "AnyFont Team" | team plan: no third-party branding |
| Trial button in the title bar | Updates button | team plan |
| Trial window on exit, purchase window | not reproduced | team plan |
| Store page in Get More | Google Fonts catalog in the same frame | team plan |
| Help menu: Product Help, About | adds Check for Updates..., Submit Ideas and Feedback..., Report a Bug... | AnyVector pattern |
| Legal Notices "Show CloudConfig.json" | omitted | no cloud config |
| Upload fonts dialog | omitted | cloud service |
| Windows (light) edit context menu in text boxes | themed egui menu, without the IME items | egui |

### Features defined but not reachable in the captured window

UI-SPEC §11 gives the full list with placements:
1. Group by family, Show recently used fonts, Use font to display font name and Show Latin names, added to the
   View menu.
2. The refresh information strip.
3. Hide/Show filter list, in the View menu.
4. Ctrl+Alt+I, which toggles the font properties panel.
5. The vendor URL link, in Font info.
6. Rename collection, in the Libraries context menu and on F2.
7. Search suggestions.
8. Glyph alternates and copy.
9. PANOSE preferences, exceptions and results, reached from Options ▸ Font Matching.
10. The Type 1 notice.
11. The flow dialogs: reboot prompt, delete, progress, "We can't find…".
12. The Download gate.
13. Toolbar overflow.
14. Font database reset with Shift held at start-up.
